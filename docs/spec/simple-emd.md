# シナリオEMD仕様

状態: Draft / 0.3  
識別子: VCD_SCENARIO_EMD_V1

## 1. 目的と例

作者が背景・出演者と粗い物語を記述し、Gemma4が複数のシーンへ展開する。MDベースのVC専用形式とし、旧EMD互換は要求しない。

```markdown
# 形式
* schema: VCD_SCENARIO_EMD_V1

# 作品
* id: homecoming
* 尺: 00:30.000
* 方針: 静かな短編映画。
* 発声: 指定台詞のみ
* BGM: なし
* 環境音: シーンに合わせて補完
* 効果音: シーンに合わせて補完

# 人物 @hero
* 名前: 少女
* 画像: hero_image
* 声質音声: hero_voice
* 特徴: 赤いコートを着た旅人。

# 背景 station
* 画像: station_image
* 情景: 夕暮れの駅前。

# 背景 florist
* 画像: なし
* 情景: 閉店した古い花屋の店先。

# シナリオ
## 展開 return
* 出演: @hero
* 背景: station
* 台詞 dlg_home: @hero | 「ただいま。」
少女が故郷へ戻り、駅を出て懐かしい町を見渡す。

## 展開 discovery
* 出演: @hero
* 背景: florist
* 発声: なし
少女は花屋の閉店を知る。店先の花を見つけ、穏やかに歩き出す。

# 固定条件 end_walking
* 内容: 最後は少女が自分の意思で歩き出す。
```

入力音声は参照であり、声質音声をそのまま最終音声へコピーしない。音声の実長で作品尺を決めない。作品尺省略時はGemma4の最終Scene終端を目標尺とする。

## 2. 文法

- UTF-8 / LF。形式・作品・一個のシナリオと、一個以上の展開を必須とする。
- 人物は`# 人物 @ID`。内部IDは@を除いた`[a-z][a-z0-9_]*`。人物集合内で一意。
- 背景・展開・固定条件の見出しは`# 背景 ID`、`## 展開 ID`、`# 固定条件 ID`。
- 人物fieldは名前が必須。特徴は記述するか、画像asset IDを指定してVision／image_factsで補完する場合に限り省略できる。画像・動画・声質音声は任意のasset ID。省略またはなしはnull。
- 背景fieldは情景を記述するか、画像asset IDを指定してVision／image_factsで補完する。背景画像なしは正常入力だが、その場合は情景が必須。
- 展開は出演と背景を一回ずつ持ち、その後の段落を原文とする。出演は@人物IDのカンマ区切りまたはなし、背景は背景ID一個。
- 固定条件は内容だけを持つ。作品の任意fieldは尺、方針、[音響方針](audio-control.md)。尺はMM:SS.mmm。音声尺指定は設けない。
- 重複・未知キー、未定義参照、空の原文は位置付きエラーとする。
- 配列を表す方針、台詞、用途別音声参照は複数recordを許可する。台詞はID、音声参照は用途と素材IDの組で重複を拒否する。単値fieldは一回だけとする。
- field区切りは最初の`: `。台詞fieldの区切りは最初の` | `で、本文内の区切り文字は`\|`へescapeする。
- 予約見出しを本文として書く場合は先頭をバックスラッシュでescapeする。
- 単一fieldの改行は`\n`、literalのバックスラッシュは`\\`として保存する。rendererもこの規則を使い、複数行本文を欠落させない。

## 3. 台詞と参照

台詞は`* 台詞 ID: @話者 | 「本文」`または`* 台詞 ID: @話者 | <d>...</d>`。人物は展開の出演者でなければならない。日本語鉤括弧はPythonがJapaneseのdタグへ変換し、既存dタグは翻訳せず保持する。

シナリオの自由文にある引用から人物をPythonが推測しない。Gemma4が発話を配置する前に、台詞recordと発声許可を確定する。説明文の引用は『』を使い、発話として誤解される表記を避ける。

音声参照は`* 音声参照 music: asset_id`などで用途別music / ambience / effectsに登録できる。同じ用途の複数素材はカンマ区切り。声質音声は人物へ割り当てる。音響が許可されない用途の参照を有効化しない。

## 4. 背景と出演

展開から生成するSceneは指定出演者・背景を保持する。変更が必要なら別展開で明記する。背景の情景・時刻・照明は人物画像の背景より優先する。未登録人物や背景を勝手に追加しない。

@人物IDはシナリオ・シーンEMDを通じて固定する。CompilerがSceneごとのSubject番号と参照素材を対応付ける。発話本文に現れた@記号は人物参照へ変換しない。

### 画像からの特徴・情景の補完

```markdown
# 人物 @hero
* 名前: 少女
* 画像: hero_image

# 背景 station
* 画像: station_image
```

この例はBuildの`vision_model_name`を有効にして使用する。Vision結果は計画用シナリオの人物description・背景descriptionへ補完し、保存する`scenes.emd`では人物の`* 特徴:`・背景の`* 情景:`として出力する。人物の観察特徴は出演する各Sceneの`subject_definitions`にも保持し、最終PlanのSubject描写へ渡す。入力のシナリオEMDとそのsource hash・台詞・音響許可は変更しない。手書きの特徴・情景があればその文章を保持し、観察事実を追記する。

画像があってもVisionが無効でimage_factsもなく、記述を補完できない場合は、推論前に`VISION_DESCRIPTION`で設定方法を案内する。音声だけ・動画だけの登録では自動画像認識による補完を行わない。完成したScene EMDでは特徴・情景を必須のままにし、保存EMDから再コンパイルできるようにする。

## 5. 作者所有

出来事、順序、結末、台詞、出演者、背景を固定条件として扱う。シーン分割、具体的動作、撮影、許可された環境音・効果音、時刻はGemma4が生成する。

シナリオとシーンEMDは別入力経路であり、シーンEMDはLLMなしで再コンパイルできる。原文位置はparserが取得し、生成シーンEMDの出典表へ保持する。
