# Gemma4計画コア

状態: Draft / 0.3

## 1. 責務

シナリオEMDからシーンEMDを生成する責務はGemma4計画コアにある。MV-DirectorのEnhancer / Timeline Plannerの構造・推論基盤を再利用し、歌詞主導の計画だけをシナリオ主導へ置き換える。

| コア | 責務 |
|---|---|
| Story Enhancer | シナリオの意図、必須出来事、固定条件、人物・背景の観察断片を統合する |
| Story Timeline Planner | シーン数・順序・接続を構成し、具体的な動作・撮影・許可音響・開始終了時刻を生成する |
| Pythonコンパイル層 | 出力の構造を検証し、不正箇所を計画コアへ返す。演出・自然文・時刻の意味を創作しない |

## 2. 処理

1. 作者の展開ID、出演者、背景、原文、必須出来事をEnhancer artifactへ整理する。
2. 展開単位にシーン構成を生成し、全体順序・状態・要求尺との整合を確認する。
3. シーン単位に演出 → 身体演技 → カメラ → 許可音響を具体化する。
4. Gemma4が作品絶対時刻とシーン内相対時刻を生成し、シーンEMDへ記述する。
5. Pythonが検証し、不正なfieldまたはSceneだけを有限回修正要求する。成功したシーンEMDを保存する。

シーン構成プレビューは同じシーンEMDの概要表示とする。独立したoutlineを物語の正本にしない。通常は検証後に自動進行でき、毎回の承認を要求しない。

## 3. Gemma4への制約

- 各Sceneの計画尺は0秒より長く15秒以内とする。
- シナリオの展開境界・出演者・背景・固定出来事・台詞を保持する。
- 出来事を見せるための動作、表情、視線、撮影を具体化する。
- 時間不足時は作者固定内容を削らず、複数Sceneへ分けて確定する。Compilerによる曖昧な情報からの分割に任せない。
- 参照画像にない情景でも作者の背景記述から展開できる。人物画像の構図・背景を持ち込まない。
- 許可時は足音、扉の軋み、衣擦れなどを動作の発生源と対応付ける。発声・歌唱・音楽を効果音として追加しない。
- 台詞の原表記「...」または既存dタグを変更せず、指定話者@heroと適用区間を持つ発話eventへ配置する。発話は翻訳へ渡さずPythonが結合する。
- 新しい主要人物、因果を変える出来事、固定結末の変更を追加しない。

具体的な時刻はLLMの推定であり、実際の動作所要時間や発話音声長を保証しない。数値の構造検証と意味・映像の評価を分ける。

## 4. protocol・推論設定

モデル探索、GGUF runtime、token事前検査、slot分離、進捗・中断、成功cacheをMV-Directorから取り込む。初期構成はGemma4 31B Q4_K_S、chat format auto、Enhancer / Plannerのn_ctx=24576、Compiler=16384、max_tokens=4096を基準とする。Vision設定は移植元の配布WF実値へ合わせる。具体的モデルファイルとfingerprintを成果物へ記録する。

新しいVC用recordを定義するが、transportは移植元と同じ行protocolを使う。

```text
RECORD_TYPE<TAB>SLOT<TAB>TEXT
```

ENHANCED、SCENES、DETAIL、TIMINGのTEXTは段階別の一行JSON。入力payload、SceneOutline、完全Scene、TimingPatch、依存は[段階別protocol](llm-protocol.md)とSchemaで定義する。未完成Sceneを完全Sceneとして検証しない。PythonがrendererでEMDを描画しても、内容と具体的時刻をGemma4が生成する責務は変わらない。

初回 → Scene単位の欠落・不正slot再要求一回 → 残存slotの単独再要求一回を上限とする。時間超過の分割要求も同じ上限内とし、無制限にシーンを増やさない。正しいslotと作者固定fieldは保持する。

context回復は任意の過去出力を縮小し、分割可能なslotを分割する。作者原文、固定条件、出演者・背景、現Scene、必要な状態、失敗理由は切り捨てない。必須内容が収まらなければContextBudgetErrorとする。OOM・model load失敗・中断は空成功にせず停止し、モデルを解放する。自動的な品質・量子化変更は行わない。

## 5. 状態・再生成

各Sceneは開始・終了状態と先行依存を持つ。人物・所持品・環境の状態を構造化して渡す。回想など作者が記述した変化はカットと状態変化へ反映する。

IDは順番から独立する。追加Sceneには新しいIDを与え、削除IDを再利用しない。並べ替えや尺変更後はGemma4が影響範囲の時刻を再生成する。Pythonは重複・欠落・状態依存の不整合を検証する。固定時刻と矛盾する場合は停止して診断する。

## 6. 受入条件

- 粗い展開一つから複数Sceneを作れ、シーン数を段落数へ固定しない。
- 全Sceneが元展開と対応し、その出演者・背景を保持する。
- 必須出来事・順序・結末と発話recordの配置を追跡できる。
- 具体的な時刻をGemma4が生成し、Pythonが格子・採用範囲へ変換する。
- 15秒超過・台詞をまたぐ分割・時刻逆転を検出し有限回回復または停止する。
- 音響補完の許可を守り、全Sceneの状態を接続する。
- 計画コアだけの試験が可能で、同じシーンEMDの再コンパイルで創作を行わない。
